# Импорт банковской выписки (Т-Банк, PDF)

Дата: 2026-11-09. Статус: ждёт проверки. Строится поверх этапа 1 (формат данных v2, копейки, `Core`).

## Контекст

Прямого доступа к личным счетам у банков нет, поэтому данные берутся из файла выписки. Первый формат: «Справка о движении средств» Т-Банка в PDF, за период, одна таблица (в образце 10 страниц, около 220 операций, все в рублях).

Образец показал структуру таблицы: колонки «Дата и время операции», «Дата списания», «Сумма в валюте операции», «Сумма операции в валюте карты», «Описание операции», «Номер карты» (последние 4 цифры); знак суммы `+` или `-`; описание переносится на несколько строк; на последней странице итоги «Пополнения» и «Расходы» и в шапке «Сумма доступного остатка на ДД.ММ.ГГГГ». Многие операции это переводы между своими договорами: «Перевод себе», «Внутренний перевод на договор …», «Перевод с договора …».

Решение по переводам между своими договорам: по умолчанию пропускаются и показываются отдельной строкой; галочка загружает их как расход или доход. Загрузка их как переводов между счетами ждёт интерфейса счетов (этап 3).

## Цель

Одна кнопка «Данные → Импорт выписки»: выбрать PDF, проверить список операций с подобранными категориями, загрузить всё за период. Повторная загрузка того же периода не создаёт дублей.

## Не входит

Другие банки и форматы (CSV и Excel Т-Банка, Сбер и другие, они добавляются позже как отдельные профили), слежение за папкой, валюты кроме рубля (такие операции показываются в списке пропущенных с пометкой), перевод внутренних переводов в операции между счетами.

## 1. Чтение PDF

- **Библиотека:** pdf.js 3.11.174, классическая сборка (`pdf.min.js` и `pdf.worker.min.js`), лицензия Apache-2.0. Файлы лежат в `web/vendor/pdfjs/`, загружаются только при первом импорте PDF (как `xlsx`). Версия закреплена, сеть не используется.
- **Политика безопасности:** в `tauri.conf.json` в CSP добавляется `worker-src 'self'`. Если воркер не запускается, pdf.js работает без воркера (`disableWorker`), импорт остаётся рабочим.
- **Модуль `web/statement.js`** без зависимости от страницы (как `core.js`, тестируется в Node):
  - `Statement.parseTbankItems(items: {str, x, y, page}[]): ParsedStatement`
  - `ParsedStatement = { ops: Op[], skipped: Skipped[], declared: {income?: number, expense?: number, balance?: number, balanceDate?: string}, warnings: string[] }`
  - `Op = { date: 'ГГГГ-ММ-ДД', time: 'ЧЧ:ММ', amount: number (копейки, со знаком), desc: string, card: string }`
- **Разбор по координатам:** заголовки колонок находятся по тексту, границы колонок берутся из их положения. Начало операции это ячейка даты в первой колонке; все последующие элементы до следующей даты, включая страницы, относятся к ней и раскладываются по колонкам. Описание склеивается из строк в порядке `y`. Сумма берётся из колонки «в валюте карты»; операция в другой валюте идёт в `skipped` с пометкой.
- **Сверка:** сумма прочитанных `+` сравнивается с «Пополнения», сумма `-` с «Расходы» (в копейках). При расхождении `warnings` содержит понятное сообщение и импорт всё равно доступен.
- **Привязка к библиотеке** это отдельная тонкая функция `extractTextItems(bytes): Promise<{str,x,y,page}[]>` в `app.js`, всё остальное чистая логика.

## 2. Категории и правила

- **Модуль `web/statement.js`:** `Statement.categorize(desc: string, rules: Rules): {type: 'in'|'out', cat: string, own: boolean}`.
- **Встроенные правила** (ключевые слова без регистра): магазины и продукты (магнит, красное&белое, пятёрочка, дикси, бристоль, лента, ашан, вкусвилл, русские пекари) в «Еда»; кафе и рестораны (бургер, вкусно и точка, кофе, coffee) в «Еда»; urent, такси, метро, транспорт в «Транспорт»; «ПФР. Пенсия» в «Пенсия»; «ПФР» прочее в «Другое»; avito, playerok и игровые магазины в «Развлечения»; «tmmb» и подписки в «Подписки»; остальное «Другое».
- **Переводы между своими** (`own = true`): описания, начинающиеся с «Перевод себе», «Внутренний перевод», «Перевод с договора», «Перевод между своими».
- **Правила пользователя:** в данных хранится `rules: { "<ключевая часть названия>": "<категория>" }`. Это необязательное поле: старые данные получают `{}` при загрузке (`Core.migrate`), версия формата остаётся 2. Правила пользователя проверяются раньше встроенных. Ключ: нормализованное название магазина (слово после «Оплата в», без цифр, в нижнем регистре).
- **Запоминание:** в окне импорта у строки, где категорию изменили, стоит галочка «Запомнить для магазина», по умолчанию включена.

## 3. Окно импорта

- Выбор PDF (диалог `open_table` принимает `pdf`; в браузере обычный выбор файла). Рядом с `xlsx`, `csv`, `json`.
- **Список операций:** дата, описание, категория (выпадающий список, ограничен списком категорий нужного типа), сумма; галочка у каждой строки (все включены). Предупреждения вверху.
- **Сводка:** найдено N, будет загружено N, дублей пропущено N, переводов между своими пропущено N (галочка «Загрузить и их как расходы и доходы» выключена), пропущено в другой валюте N.
- **Сверка остатка:** если в справке есть «доступный остаток», показываются «В справке: X ₽» и «У вас после импорта: Y ₽» с разницей. Если период справки начинается с первой записи бюджета, предлагается кнопка «Подогнать стартовый остаток под справку» (меняет общий стартовый остаток через `Core.setOpeningTotal`); без неё остаток не меняется.
- **Загрузка:** записи получают `type`, `date`, `time`, `title` (очищенное описание), `cat`, `amount` (по модулю), `account` (первый счёт); месяцы создаются; `save()`; уведомление «Загружено: N».

## 4. Дубли

`Core.splitNewItems` учитывает `time`: ключ `дата|время|тип|описание|сумма`, а для записей без `time` прежний ключ. Для записей со временем сравнение как с мультимножеством: если в выписке две одинаковые операции в одну минуту (например, два одинаковых платежа), загружаются обе; при повторной загрузке тех же двух они обе пропускаются, а при дозагрузке третьей загружается только третья.

## 5. Приватность

- Файл нигде не сохраняется и не отправляется, читается в памяти.
- В названиях маскируются телефоны (`+7 *** ***-77-71` → `+7···7771`: остаются последние 4 цифры) и номера договоров (последние 4 цифры); ФИО, адрес и номера счетов шапки не читаются и не сохраняются.
- Номер карты в запись не попадает.

## 6. Тесты

Только выдуманные данные, ничего из реального образца не копируется в репозиторий.

- `tests/statement.test.js` на синтетических элементах текста `{str,x,y,page}`: операция в одну строку, описание на несколько строк, операция через границу страницы, плюс и минус, суммы с пробелами-разделителями («-2 508.00 ₽»), операция в долларах попадает в `skipped`, сверка итогов (совпадает и не совпадает), пустая таблица даёт предупреждение «Не нашёл операций».
- `categorize`: встроенные правила, правило пользователя раньше встроенного, переводы между своими, неизвестное название даёт «Другое».
- Маскирование телефонов и номеров договоров.
- `splitNewItems` с временем: две одинаковые в одну минуту, повторная загрузка, дозагрузка третьей.
- `migrate`: данные без `rules` получают `{}`.
- Ручная проверка на реальном образце (локально, вне репозитория): число операций и итоги совпадают со справкой, предупреждения нет.

## Критерии готовности

- Реальная справка Т-Банка читается: число операций и суммы «Пополнения» и «Расходы» совпадают с итогами в справке, предупреждения нет.
- Переводы между своими пропущены по умолчанию и считаются в сводке.
- Повторная загрузка той же справки даёт «Загружено: 0, дублей: N».
- Все тесты проходят локально и в CI, импорт работает в собранном приложении для macOS и Windows (воркер pdf.js запускается или есть запасной путь).
- Релиз 1.3.0 (после слияния этапа 1) с описанием в `CHANGELOG.md` и разделом в `README.md`.

## Риски

- **Макет PDF.** Банк может изменить оформление справки: разбор привязан к заголовкам колонок, а сверка с итогами сразу покажет проблему.
- **Воркер pdf.js под CSP.** Предусмотрен запасной путь без воркера; проверка в собранном приложении обязательна.
- **Размер.** pdf.js добавляет около 1,3 МБ файлов, но не влияет на запуск (грузится по требованию).
- **Неверные категории.** Подбор по ключевым словам ошибается; поэтому все категории видны и меняются до загрузки, исправления запоминаются.
