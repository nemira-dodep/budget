# Этап 1. Фундамент данных

Дата: 2026-11-09. Статус: ждёт проверки.

## Контекст

Приложение «Бюджет» (Tauri 2, интерфейс на HTML/CSS/JS без сборки) хранит все данные в `localStorage` окна приложения. Суммы только целые рубли, счёт один, тестов нет.

Общий проект разбит на три этапа, у каждого своя спека, план и релиз:

1. **Фундамент данных** (эта спека).
2. **Интерфейс «всё на виду»:** один экран из четырёх зон без прокрутки страницы, «можно тратить в день», таблица строк для английского.
3. **Новые возможности:** тренды по месяцам, поиск по всем месяцам, интерфейс счетов, автозапуск, импорт банковских выписок, английский интерфейс.

Выбранные решения: один экран из четырёх зон (слева месяцы и счета, сверху плитки, по центру записи, справа категории, лимиты, цели; остальное панелью поверх); счета как кошельки с переводами; автокопии в папку приложения с возможностью выбрать свою; подписи кодом и сборка для Linux не делаются.

## Цель этапа

Данные не теряются при очистке окна или переустановке, суммы поддерживают копейки, модель готова к нескольким счетам, ключевая логика покрыта тестами.

## Не входит в этап

Интерфейс счетов и переводов, новый экран, английский, тренды, импорт выписок, автозапуск. Здесь только модель, хранение и тесты.

## 1. Хранение

**Файл данных.** `data.json` в папке данных приложения (`app_data_dir`). Rust пишет файл через временный файл в той же папке и переименование, поэтому обрыв записи не оставляет повреждённый файл.

**Команды Rust:**
- `load_data` возвращает текст файла или `null`, если файла нет.
- `save_data(text)` проверяет, что текст является корректным JSON, и пишет атомарно.
- `get_backup_dir`, `choose_backup_dir` (диалог выбора папки), `open_backup_dir`.

**Интерфейс.** Данные живут в памяти (`S`). После изменения `save()` ставит отправку в Rust с задержкой 300 мс (повторные вызовы сбрасывают таймер) и принудительно отправляет данные при закрытии окна. Ошибка записи показывается уведомлением и не теряет данные в памяти.

**Перенос со старой версии.** Если `load_data` вернул `null`, интерфейс читает `budget.v1` из `localStorage`, переводит в формат v2 и отправляет в Rust. Старый ключ не удаляется. Если нет ни файла, ни старых данных, создаётся пустой бюджет.

**Режим браузера** (нет `window.__TAURI__`): как сейчас, через `localStorage`, тот же формат v2.

**Повреждённый файл.** Если `data.json` не читается, приложение не затирает его: показывает сообщение, предлагает восстановить из последней копии и оставляет повреждённый файл рядом под именем `data.json.broken`.

## 2. Автокопии

- При запуске и после сохранения Rust проверяет, есть ли копия за сегодня (`budget-ГГГГ-ММ-ДД.json`). Если нет, копирует `data.json`.
- После создания копии удаляются копии старше 30 дней (по дате в имени файла; файлы с другими именами не трогаются).
- Папка по умолчанию: `<app_data_dir>/backups`. Свою папку можно выбрать в меню «Данные → Папка копий»; выбор хранится в `settings.json` рядом с данными. Если выбранная папка недоступна, копии идут в папку по умолчанию и показывается предупреждение.
- Кнопка «Открыть папку копий» открывает её в Finder или Проводнике.
- Ручные «Сохранить копию» и «Загрузить копию» остаются.

## 3. Деньги и модель данных (формат v2)

**Деньги.** Целые числа в копейках. Показ: «1 500 ₽», копейки только если они есть: «1 500,50 ₽». Ввод принимает «1500,50» и «1500.50», пробелы убираются, больше двух знаков после запятой округляются до копейки.

**Структура:**

```
{
  version: 2,
  accounts: [{ id, name, opening }],          // opening в копейках
  cats: { in: [...], out: [...] },
  limits: { "Категория": копейки },
  goals: [{ id, name, target, saved }],       // в копейках
  reminders: [...],                           // без изменений
  months: ["2026-11", ...],
  cur: "2026-11",
  items: [{
    id, t, date, title, note?, rep?, src?,
    type: "in" | "out" | "transfer",
    amount,                                    // копейки, > 0
    account,                                   // id счёта
    cat,                                       // для in и out
    toAccount                                  // только для transfer
  }]
}
```

**Правила подсчёта.**
- Остаток счёта = стартовый остаток + доходы − расходы ± переводы по этому счёту.
- Общий остаток = сумма остатков счетов. Перевод между счетами не меняет общий остаток и не входит в доходы и расходы.
- Месячный остаток считается как сейчас: начало месяца равно концу предыдущего, внутри месяца записи идут по дате и порядку добавления.
- Поле `opening` на верхнем уровне (v1) заменяется стартовыми остатками счетов. Общий стартовый остаток равен их сумме.
- Нельзя удалить счёт, у которого есть записи. Должен оставаться хотя бы один счёт.

**Перенос v1 → v2.** Суммы, лимиты, цели умножаются на 100 с округлением. `opening` становится счётом «Основной», все записи привязываются к нему. Остальные поля сохраняются как есть. Перенос идемпотентен: данные v2 при загрузке не меняются, неизвестные поля не теряются.

**Резервные копии и импорт.** Копии `.json` версии 1 открываются и переносятся в v2. Копии v2 открываются как есть. Импорт таблиц (`.xlsx`, `.csv`) читает суммы с копейками и привязывает записи к первому счёту.

## 4. Структура кода и тесты

**Модуль `web/core.js`** без зависимости от страницы (подключается тегом `<script>`, в Node через `require`). Содержит: форматирование и разбор денег, перенос v1 → v2, подсчёт месяцев и остатков счетов, разбор листа таблицы. `app.js` использует его через `window.Core`.

**Тесты на Node** (`node --test`, без зависимостей), папка `tests/`:
- деньги: разбор «1500,50», «1 500», «1500.5», отказ на тексте; форматирование с копейками и без;
- перенос v1 → v2: суммы ×100, счёт «Основной», сохранение неизвестных полей, идемпотентность;
- подсчёт: остаток по месяцам, переход между месяцами, переводы не влияют на общий остаток и на доходы и расходы, остатки отдельных счетов;
- разбор таблицы: колонки, строки-месяцы, копейки, дубли.

**Тесты на Rust** (`cargo test` в `src-tauri`): атомарная запись (старый файл цел при ошибке), создание копии за день только один раз, очистка копий старше 30 дней и безопасность для чужих файлов.

**CI.** Отдельное задание `test` в `build.yml` запускает оба набора перед сборкой установщиков; сборка зависит от его успеха.

## Критерии готовности

- На существующих данных (v1 в `localStorage`) приложение при первом запуске создаёт `data.json`, суммы и остатки совпадают с прежними.
- После перезапуска данные на месте; повреждённый `data.json` не затирается.
- Копия за сегодня создаётся один раз, старше 30 дней удаляются, папку можно сменить и открыть.
- Ввод копеек работает в форме записи, при редактировании и при импорте.
- Все тесты проходят локально и в CI.
- Релиз 1.2.0 собирается и обновляется с 1.1.0 без потери данных.

## Риски

- **Миграция денег.** Ошибка в переносе заденет все данные. Снижение риска: тесты переноса, неудаляемый ключ `budget.v1` и копия перед первой записью `data.json`.
- **Закрытие окна во время записи.** Принудительная отправка при закрытии и атомарная запись.
- **Правила целостности счетов** (удаление, переводы) без интерфейса проверяются только тестами. Интерфейс появится в этапе 3.
